# CS0535 — Interface member not implemented

## Pattern
`error CS0535: 'T' does not implement interface member 'I.M'`

## Root Causes (ordered by likelihood)
1. A base class or interface was updated (e.g., NT8 version upgrade) and added new abstract members that existing subclasses don't implement
2. A class declares it implements an interface but is missing one or more required method/property overrides
3. An abstract base class in DEEP6 added a new abstract member and derived classes weren't updated

## ESCALATION POLICY

**This error ALWAYS emits `NEEDS_HUMAN`.**

CS0535 requires understanding the full interface contract and the class's intended behavior for each missing member. Automated pattern matching cannot safely generate correct implementations without knowing the business logic. Generating stub implementations risks silent behavioral bugs that are harder to find than the compile error.

**Do not attempt to auto-fix CS0535. Always escalate.**

## Fix Strategies

### Strategy 1: NEEDS_HUMAN — List missing members and escalate
- **Detect**: The error message names the class and the interface member(s) not implemented.
- **Lookup**: Read the interface or abstract base class declaration to find the full signature of each missing member. List all missing members from the error output.
- **Fix**: **Emit NEEDS_HUMAN.** Provide the human with:
  1. The class name that has the error
  2. The interface or base class name
  3. The full list of missing member signatures
  4. The file path in the repo source
- **Verify**: Human implements the missing members with correct business logic, then runs `nt8-ai-loop.ps1` to confirm compile success.

**Output format for NEEDS_HUMAN:**

```
NEEDS_HUMAN: CS0535 in <ClassName>

File: ninjatrader/Custom/<path>/<File>.cs
Class: <ClassName>
Interface/Base: <InterfaceName>

Missing members (must be implemented by a human):
  - <ReturnType> <MethodName>(<Parameters>)
  - <ReturnType> <PropertyName> { get; set; }
  ...

Reason: CS0535 requires business-logic-aware implementation.
        Auto-generated stubs would compile but produce incorrect behavior.
        A human must implement each member with the correct logic.
```

## NT8-Specific Notes

- NT8 indicators must implement `OnBarUpdate()` (abstract on `Indicator` base). If missing, CS0535 fires.
- NT8 strategies must implement `OnBarUpdate()` (abstract on `Strategy` base).
- Custom interfaces in DEEP6 (e.g., a signal interface) may add members over time. When a new member is added to the interface, all implementing classes must be updated.
- NT8 version upgrades occasionally add new abstract members to base classes. After an NT8 upgrade, CS0535 on existing files signals a breaking change in the NT8 API.

## Common NT8 Abstract Members

| Base Class | Required Override |
|------------|-------------------|
| `Indicator` | `OnBarUpdate()` |
| `Strategy` | `OnBarUpdate()` |
| `DrawingTool` | `OnRender(ChartControl, ChartScale)`, `OnMouseDown(ChartControl, ChartScale, ChartMouseEventArgs)` |
| `MarketAnalyzerColumn` | `OnBarUpdate()`, `Calculate()` |
| `AddOnBase` | `OnWindowCreated(Window)`, `OnWindowDestroyed(Window)` |

## Example Fix (human-authored, not auto-generated)

```diff
  // CS0535: DEEP6SignalProcessor does not implement ISignalProcessor.Reset
  public class DEEP6SignalProcessor : ISignalProcessor
  {
      public double Score { get; private set; }
      public void Update(FootprintBar bar) { ... }
-     // Missing: void Reset() — CS0535
+
+     // Human implements with correct business logic:
+     public void Reset()
+     {
+         Score = 0.0;
+         _absorptionCount = 0;
+         _exhaustionCount = 0;
+     }
  }
```
