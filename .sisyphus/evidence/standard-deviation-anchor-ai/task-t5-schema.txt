## Capture Protocol — Defined

  [x] Trigger: bar close when Pine emits state change
  [x] Atomic capture: screenshot + structured fields simultaneously
  [x] No intrabar captures
  [x] State transitions enumerated (candidate, confirmed, active, invalidated, superseded)
  [x] Each transition = new record with own anchor_id

## Leakage-Prevention Rules — Explicit

  [x] R1: Decision-time fields immutable after capture
  [x] R2: outcome_label is null at capture time — no exceptions
  [x] R3: Outcome written only after outcome bar closes
  [x] R4: Screenshot taken at decision time, never retroactively
  [x] R5: No future data in structured fields
  [x] Immutability contract: fields categorized as IMMUTABLE / WRITE-ONCE / MUTABLE
  [x] Outcome resolver is a SEPARATE process from capture bridge

## Storage Layout — Defined

  [x] Screenshots: data/sd_anchor/screenshots/{YYYY-MM-DD}/{anchor_id}.png
  [x] Records: data/sd_anchor/records/{YYYY-MM-DD}.jsonl
  [x] Date partitioning by captured_at (UTC)
  [x] Paths stored as relative from repo root
  [x] JSONL format with example record
  [x] Append-only retention policy

## Validation Rules — Defined

  [x] UUID, timestamp, enum, range, level ordering checks
  [x] Bullish and bearish level ordering specified
  [x] Screenshot existence required before record write
